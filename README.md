# DeviceLock (기기 제한 앱)

Device Owner 권한으로 동작하는 개인용 기기 제한 앱입니다.

| 기능 | 구현 방식 |
|---|---|
| 제거 방지 | `setUninstallBlocked` + 강제 종료/데이터 삭제 차단(Android 11+는 앱 단위, 10은 전체 앱 제어 차단) + 안전 모드·사용자 추가 차단 |
| 디버깅 차단 | 릴리스 빌드에서만 `DISALLOW_DEBUGGING_FEATURES` 적용 (디버그 빌드는 개발을 위해 제외) |
| 시간 강제 | 자동 시간·시간대 강제 + 수동 변경 메뉴 차단 |
| 앱 차단 | `setPackagesSuspended` (오버레이·상주 서비스 없음), 요일/시간대/날짜 범위 조건, 그룹. 삭제된 앱·재설치·예외 상황 처리 포함(아래) |
| 네트워크 화이트리스트 | 프록시(닫힌 전역 프록시 + 예외 목록), 내장 DNS VPN(제한적인 DNS 질의 필터), Private DNS(DoT 리졸버 지정)를 선택. 프록시와 내장 DNS VPN은 함께 선택할 수 있고 Private DNS와 내장 DNS VPN은 동시에 선택하지 않음. Private DNS 단독은 허용 목록 차단 기능이 아님 |
| 도메인 허용 규칙 | 요일/시간대/날짜 범위 조건이 맞는 동안에만 도메인(과 하위 도메인)을 허용. 그룹으로 묶어 켜고 끌 수 있음 |
| 앱 제거 | 비밀번호를 새로 입력하면 모든 제한을 풀고 Device Owner 를 내려놓은 뒤 시스템 제거 화면을 띄움(강력 모드에서는 24시간 대기가 끝난 구간에서만) |
| 위치 예외 | 규칙마다 "위치 반경(50m~10km) + 시간대"를 지정. 반경 안이고 그 시간대면 해당 규칙을 일시 비활성화 |
| 강력 모드 | 한 번 켜면 앱에서 끌 수 없음. 이후 규칙 변경·앱 제거 전에 비밀번호 입력 → 24시간 대기. 일반 앱 인터넷은 로컬 VPN lockdown으로 차단하나 일부 시스템 앱은 Android가 VPN 예외로 처리할 수 있음 |
| 비밀번호 | PBKDF2 해시 저장, 복구 기능 없음, 연속 실패 시 대기 시간 증가, 입력 후 5분간 편집 가능 |
| 공장 초기화 | 막지 않음 (최후의 복구 수단) |


## 네트워크 화이트리스트 동작과 한계

- `setRecommendedGlobalProxy` 로 프록시를 `127.0.0.1:9`(열려 있지 않은 포트)로 지정하고, 허용 도메인을 프록시 **예외 목록**에 넣습니다. 예외 목록의 주소는 프록시를 거치지 않고 바로 접속하며, 나머지는 닫힌 포트로 가서 실패합니다.
- 도메인 하나를 넣으면 `도메인`과 `*.도메인` 두 항목이 들어갑니다(클라이언트마다 와일드카드 해석이 달라서).
- 시스템 연결 확인용 주소(`connectivitycheck.gstatic.com` 등)는 항상 허용합니다.
- **한계**: `setRecommendedGlobalProxy` 는 이름 그대로 권장 프록시 설정입니다. 시스템 프록시 설정을 따르는 앱(브라우저, 일부 HTTP 앱)만 걸러집니다. 프록시를 무시하는 앱(일부 게임·메신저의 자체 소켓, UDP/QUIC 직접 연결 등)은 이 방식으로 막을 수 없습니다. 더 넓게 거르려면 위 "내장 DNS VPN" 방식을 함께 또는 대신 선택하세요. Android 공식 API도 이 설정이 모든 앱에 강제되는 프록시가 아니라고 설명합니다.
- 안드로이드는 형식이 틀린 프록시 설정을 **조용히 무시**합니다. 그래서 입력 단계에서 같은 규칙으로 걸러내고(한글 도메인의 punycode `xn--` 처럼 하이픈이 연속되는 주소, IPv6, 점 없는 이름은 거부), 적용 후 실제 반영 여부를 확인해 상태 카드에 표시합니다.
- 예외 목록 길이 한도(5000자)가 있어 허용 도메인이 너무 많으면 저장이 거부됩니다.
- 허용 규칙이 하나도 없는 채로 켜면 인터넷이 사실상 모두 끊깁니다(켤 때 경고).

## 차단 방식 (메인 화면 > 네트워크 화이트리스트 > 차단 방식 선택)

| 방식 | 동작 | 타사 VPN 과 함께 | 한계 |
|---|---|---|---|
| 프록시 | 아래 "네트워크 화이트리스트 동작과 한계" 참고 | 타사 VPN과 병행할 수 있는 경우가 있으나, VPN·앱이 프록시를 따르는지에 따라 다름 | 프록시를 무시하는 앱은 못 막음 |
| 내장 DNS VPN | 이 앱의 로컬 VPN 이 DNS 주소 하나(`10.255.255.1/32`)로 들어오는 IPv4 UDP 53 질의를 처리. 허용 도메인(하위 도메인 포함)은 1.1.1.1 → 8.8.8.8 로 전달하고 나머지는 NXDOMAIN 으로 응답. 요일·시간 규칙 반영 | 불가. Android는 VPN 인터페이스를 동시에 하나만 활성화 | IP 직접 접속, 자체 DoH/DoT, TCP 53, IPv6 기반 우회 및 여러 DNS 패킷 형태를 완전히 처리하지 못함. 정밀한 방화벽이 아님 |
| Private DNS | 지정한 DNS-over-TLS 호스트를 전역 설정 | 타사 VPN과 함께 쓸 수 있는 경우가 있지만, DNS 서버가 VPN 내부·외부 경로 모두에서 도달 가능해야 함 | DNS 서버만 지정. 이 앱의 허용 목록·요일·시간 규칙은 적용되지 않음. 해당 DNS 서비스에서 허용 목록을 별도로 설정해야 함 |

- VPN 권한 허용이 필요합니다(메인 화면의 "VPN 권한 허용" 버튼). VPN을 하나만 활성화할 수 있으므로 내장 DNS VPN이나 강력 모드는 타사 VPN을 대체합니다. 종료할 때 이전에 Always-on 으로 지정되어 있던 VPN 패키지와 lockdown 설정을 복원하도록 했지만, 사용자가 임시로 켠 일반 VPN 연결까지 복원할 수는 없습니다.
- 내장 DNS VPN 은 시간 동기화용 `time.android.com`, `pool.ntp.org` 와 연결 확인 주소를 항상 허용합니다. 기기 자체 Private DNS 또는 앱 자체 DoH/DoT 를 쓰는 경우 이 DNS 필터를 우회할 수 있습니다.
- Private DNS는 처음 변경하기 전 모드·호스트를 저장해 복원합니다. 단, DevicePolicyManager 에는 Private DNS를 OFF 로 되돌리는 메서드가 없으므로 원래 OFF 였던 기기는 해제 시 자동(기회적) 모드로 전환됩니다. Android 공식 API의 지원 메서드는 지정 호스트 설정과 자동 모드 설정입니다.

## 위치 예외

- 규칙(앱 차단 / 도메인 허용) 편집 화면의 "위치 예외"를 켜고 위도·경도·반경(100/200/300/500/1000m 또는 직접 입력)과 예외 시간대(예: 21:00~06:00)를 지정합니다. "현재 위치 사용"은 기기의 마지막 위치를 채웁니다.
- 기기가 반경 안에 있고 현재 시각이 예외 시간대이면 그 규칙은 꺼진 것으로 계산됩니다(앱 규칙은 차단 해제, 도메인 규칙은 허용 해제).
- **위치를 모르거나 5분 넘게 갱신되지 않았으면 예외는 적용되지 않고 규칙이 유지됩니다**(실패하면 제한 쪽으로). 모의 위치(mock), 정확도 100m 초과 위치는 무시합니다. 위치 오차 반경까지 더한 값이 설정 반경 안에 있어야 예외가 발동합니다.
- 예외 시간대와 원래 규칙 시간대가 모두 활성인 동안에만 2분 간격으로 GPS·네트워크 위치 업데이트를 요청합니다. 상주 서비스는 없습니다. 배터리·실내 위치 정확도·제조사 절전 정책에 따라 실제 반응이 늦거나 예외가 아예 발동하지 않을 수 있습니다. 기기 위치 설정이 꺼져 있으면 예외가 적용되지 않습니다.
- 위치 권한은 Device Owner 권한으로 자동 부여를 시도합니다. Android 12 이상 일부 기기에서는 거부될 수 있으며, 그 경우 메인 화면의 "앱 권한 설정 열기"로 "항상 허용"을 직접 지정해야 합니다.

## 강력 모드

1. 메인 화면 "강력 모드" 스위치를 켭니다(비밀번호 필요). **한 번 켜면 끌 수 없습니다.**
2. 켠 뒤에는 규칙 변경, 그룹·규칙 추가/삭제, 차단 방식 변경, 앱 제거 등을 하려 할 때 비밀번호를 입력하면 **24시간 대기**가 시작됩니다. 대기 중에는 이 앱의 로컬 VPN lockdown으로 일반 앱의 인터넷 연결을 차단합니다. 다만 Android 시스템 앱은 VPN을 우회할 수 있으므로 기기 전체의 모든 통신이 100% 차단된다고 보장할 수는 없습니다.
3. 대기 중에는 언제든 "대기 중단"을 할 수 있습니다. 네트워크는 바로 복구되지만, 다시 비밀번호를 입력하면 **24시간을 처음부터** 기다려야 합니다. VPN 권한이 승인되지 않았다면 타이머는 시작되지 않으며, 권한 승인 후 다시 비밀번호를 입력해야 합니다.
4. 대기가 끝나면 **30분 동안만** 규칙을 바꿀 수 있습니다(이때도 편집 전에 비밀번호를 한 번 더 입력). 30분이 지나면 다시 대기가 필요합니다.
5. 대기 중 차단은 이 앱의 로컬 VPN 으로 일반 앱 트래픽을 버리고, 상시 VPN 차단(lockdown)을 거는 방식입니다. Android 시스템 앱은 VPN 예외가 될 수 있습니다. 대기 중 진행 상황은 재부팅해도 유지됩니다. 타사 Always-on VPN 설정은 저장·복원을 시도하지만, 임시 연결은 대기 후 다시 직접 연결해야 할 수 있습니다.
6. 경과 시간은 같은 부팅 안에서는 단조 시계로, 재부팅 뒤에는 벽시계로 계산합니다. 시간 수동 변경은 Device Owner 정책으로 막혀 있습니다.
7. 강력 모드에서도 **공장 초기화는 막지 않습니다**(최후의 복구 수단). 이를 막으면 비밀번호 분실 시 기기를 되살릴 방법이 없어집니다.

## 서명 키 만들기 (GitHub Actions, 업데이트 설치용)

릴리스 APK 를 매번 **같은 키**로 서명해야 이전 설치 위에 업데이트가 됩니다(키가 다르면 "서명이 다르다"며 설치 실패). 키스토어는 저장소에 올리지 않고 GitHub Secrets 에만 둡니다.

1. PC 에서 한 번만 키스토어를 만듭니다.

```
keytool -genkeypair -v -keystore release.jks -alias devicelock -keyalg RSA -keysize 2048 -validity 36500
base64 -w0 release.jks      # macOS: base64 -i release.jks
```

2. 저장소 Settings > Secrets and variables > Actions 에 다음 4개를 등록합니다.

| 이름 | 값 |
|---|---|
| `KEYSTORE_BASE64` | 위 base64 출력 전체 |
| `KEYSTORE_PASSWORD` | 키스토어 비밀번호 |
| `KEY_ALIAS` | `devicelock` (위에서 정한 별칭) |
| `KEY_PASSWORD` | 키 비밀번호 |

3. `release.jks` 와 비밀번호는 **따로 안전하게 백업**하세요. 잃어버리면 이후 업데이트 설치가 불가능합니다.
4. Secrets 가 없으면 워크플로가 실패하며 안내 메시지를 냅니다(실수로 다른 키로 서명되는 것을 막기 위함). 빌드 로그의 "Show signing certificate" 단계에서 인증서 SHA-256 지문이 매번 같은지 확인할 수 있습니다.
5. `versionCode` 는 `run_number × 1000 + run_attempt` 로 계산해 같은 실행의 재실행에서도 증가합니다.
6. **이미 설치된 예전 빌드(CI 가 임시 디버그 키로 서명한 것)는 새 키 APK 로 업데이트되지 않습니다.** 예전 빌드에서 "비밀번호로 앱 제거"를 한 뒤 새 APK 를 설치하고 Device Owner 를 다시 설정해야 합니다.

## 삭제·재설치 처리

- 규칙에 등록된 앱이 삭제되면 상태 카드에 "설치되지 않은 규칙 앱"으로 따로 표시하고(시스템 거부와 구분), 규칙은 유지됩니다.
- 앱을 삭제했다가 다시 설치하면 일시중지 상태가 사라지므로, 다시 차단해야 합니다. 앱 삭제는 `PACKAGE_FULLY_REMOVED` 로 즉시 감지하고, 미설치 앱이 있는 동안에는 5분마다, 평소에는 30분마다 다시 평가합니다. (Android 8 이상에서는 `PACKAGE_ADDED` 를 매니페스트로 못 받을 수 있어 짧은 주기 평가를 겸합니다. 재설치 직후 최대 5분 정도는 열릴 수 있습니다.)
- 앱 선택 창은 열려 있는 동안 설치/삭제 이벤트를 받아 목록을 자동 갱신하고, 이미 선택했지만 삭제된 앱도 목록에 남겨 선택을 해제할 수 있게 합니다.

## 비밀번호로 앱 제거

메인 화면 맨 아래 "비밀번호로 앱 제거". 편집 잠금 해제와 별개로 비밀번호를 매번 새로 확인하고, 한 번 더 확인한 뒤 다음 순서로 진행합니다: 앱 차단 해제 → 프록시·VPN·Private DNS·위치 확인 해제 → 사용자 제한 해제 → 제거 차단 해제 → `clearDeviceOwnerApp` → 시스템 제거 화면. 기존 Always-on VPN 과 Private DNS 구성을 가능한 범위에서 복원합니다. 네트워크 복원에 실패하면 Device Owner 해제를 중단합니다.

**중요한 Android 제한:** `DevicePolicyManager.clearDeviceOwnerApp()` 은 API 26부터 폐기되었고, 공식 문서는 테스트 용도만을 전제로 안내합니다. 호출이 성공한다고 보장되지 않으며, 일부 정책은 해제 후에도 남을 수 있습니다. 따라서 앱 내 비밀번호 제거 기능은 테스트 기기에서 먼저 검증해야 하며, 생산 기기에서 Device Owner를 확실히 해제하는 보장된 방법은 아닙니다. 공식 문서는 민감한 기기 데이터 보호를 위해 공장 초기화를 권고합니다.

1. Android Studio에서 `DeviceLock` 폴더를 엽니다. Gradle 동기화가 끝날 때까지 기다립니다.
2. 버전 관련 오류가 나면 AGP 8.7.3, Kotlin 2.0.21, Compose BOM 2024.12.01 을 설치된 Studio에 맞게 올려 주세요.
3. 개발 중에는 Studio의 Run으로 설치하는 것을 권장합니다. 일반적으로 이 방식은 테스트용 플래그가 붙어 adb로 Device Owner를 해제할 수 있습니다(확실하지 않으므로 반드시 테스트 기기로 먼저 확인하세요).

## Device Owner 설정

1. 기기에서 모든 계정(구글 등)을 제거합니다.
2. 개발자 옵션에서 USB 디버깅을 켜고 PC와 연결합니다.
3. 앱을 설치한 뒤 PC에서 실행합니다.

```
adb shell dpm set-device-owner app.devicelock/.DeviceLockAdminReceiver
```

4. 앱을 열고 비밀번호를 설정합니다.

제조사에 따라 이 명령이 거부될 수 있습니다.

## 주의

- 릴리스 빌드를 Device Owner로 설정하면 디버깅이 막혀 adb로도 되돌릴 수 없고, 공장 초기화만 가능합니다. **주 기기에 적용하기 전에 테스트 기기에서 먼저 검증하세요.**
- 앱은 자기 자신, 전화, 설정, 런처 등 시스템이 일시중지를 거부하는 패키지는 차단하지 못합니다. 거부된 패키지는 상태 카드에 빨간 글씨로 표시됩니다.
- Android 12/12L에서는 정확 알람 권한이 없으면 규칙 전환이 몇 분 늦을 수 있습니다. Android 13 이상은 자동으로 허용됩니다.
- 시간 서버는 시스템이 정하며 앱이 지정할 수 없습니다.
- 막지 않는 것(의도): 공장 초기화, 출처를 알 수 없는 앱 설치. 같은 서비스의 다른 패키지(비공식 앱 등)를 설치하면 별도 규칙이 필요합니다.

## 1단계 검증 체크리스트 (실기기)

1. Device Owner 설정 후 앱의 상태 카드에 실패 항목이 없는지 확인
2. 설정 > 앱 에서 이 앱의 삭제, 강제 종료, 저장공간 삭제가 막혀 있는지 확인
3. 날짜/시간 설정을 수동으로 바꿀 수 없는지 확인
4. 테스트 앱 하나로 규칙을 만들어 지금 시각에 걸리게 하고 실행/알림이 막히는지 확인
5. 시간대를 바꿔 규칙 경계(예: 1~2분 뒤)에서 자동으로 적용·해제되는지 확인
6. 재부팅 후에도 상태가 유지되는지 확인
7. 비밀번호 없이 규칙을 수정할 수 없는지, 5회 오입력 시 대기가 걸리는지 확인
8. 규칙에 등록한 앱을 삭제했다가 다시 설치했을 때, 몇 분 안에 다시 차단되는지 / 삭제 중에 상태 카드에 "설치되지 않은 규칙 앱"으로 뜨는지 확인
9. 화이트리스트를 켜고 허용 도메인 하나만 등록한 뒤, 크롬에서 허용 사이트는 열리고 다른 사이트는 막히는지 확인. 상태 카드에 네트워크 오류가 없는지 확인
10. 도메인 허용 규칙을 "지금 시각이 아닌 시간대"로 만들면 막히고, 시간대를 포함하게 고치면 열리는지 확인 (경계 시각에서 자동 전환되는지도)
11. 삼성 보안 폴더·듀얼 메신저·보조 사용자 추가가 막혀 있는지 확인(제조사별로 다를 수 있음)
12. **테스트 기기에서 먼저** "비밀번호로 앱 제거"를 눌러 Device Owner 해제 → 제거까지 끝나는지 확인 (`clearDeviceOwnerApp` 은 공식 문서상 테스트 용도이며, 실제 기기에서 성공을 보장하지 않음)

13. 차단 방식을 "내장 DNS VPN"으로 바꾸고 VPN 권한을 허용한 뒤, 허용 도메인은 열리고 그 외는 막히는지, 허용 규칙을 시간대 밖으로 만들면 막히는지 확인
14. 위치 예외: 규칙에 현재 위치·반경 200m·"지금 시각이 포함되는 시간대"로 예외를 걸어 규칙이 꺼지는지, 반경 밖으로 이동하거나 위치를 끄면 다시 적용되는지 확인. 상태 카드의 위치 권한·위치 오류 표시 확인
15. **테스트 기기에서 먼저** 강력 모드를 켜고: 비밀번호 입력 시 일반 앱의 인터넷이 끊기는지(일부 시스템 앱은 예외 가능), "대기 중단"으로 즉시 복구되는지, 중단 후 다시 비밀번호를 넣으면 24시간이 처음부터인지, 재부팅 후에도 대기 상태가 유지되는지 확인(24시간 전체를 기다리지 않고 확인하려면 코드의 `StrongMode.WAIT_MS` 를 임시로 줄여 빌드)
16. 강력 모드에서 스위치가 꺼지지 않는지, 대기 전에는 규칙 수정·앱 제거가 막히는지 확인

## 스마트 스위치 (실험 기능)

삼성 스마트 스위치는 Device Owner 상태에서 기본 차단됩니다. 앱 메인 화면의 "스마트 스위치 허용" 스위치를 켜면
`com.sec.android.easyMover` 에 관리 구성 값 `allow_run=true` 를 넣습니다. 이 방식이 실제로 동작하는지는 검증되지 않았으므로 실기기에서 확인이 필요합니다.

같은 스위치가 `setBackupServiceEnabled`(백업 서비스 허용)도 함께 제어합니다. 관리 서비스 문서들이 두 설정을 같이 켜라고 안내하기 때문입니다. 끄면 백업 서비스는 다시 비활성이 됩니다.
