# DeviceLock (기기 제한 앱)

Device Owner 권한으로 동작하는 개인용 기기 제한 앱입니다.

| 기능 | 구현 방식 |
|---|---|
| 제거 방지 | `setUninstallBlocked` + 강제 종료/데이터 삭제 차단(Android 11+는 앱 단위, 10은 전체 앱 제어 차단) + 안전 모드·사용자 추가 차단 |
| 디버깅 차단 | 릴리스 빌드에서만 `DISALLOW_DEBUGGING_FEATURES` 적용 (디버그 빌드는 개발을 위해 제외) |
| 시간 강제 | 자동 시간·시간대 강제 + 수동 변경 메뉴 차단 |
| 앱 차단 | `setPackagesSuspended` (오버레이·상주 서비스 없음), 요일/시간대/날짜 범위 조건, 그룹. 삭제된 앱·재설치·예외 상황 처리 포함(아래) |
| 네트워크 화이트리스트 | 전역 프록시를 닫힌 포트로 지정하고 허용 도메인만 프록시 예외 목록에 넣는 방식. VPN·상주 서비스 없음 |
| 도메인 허용 규칙 | 요일/시간대/날짜 범위 조건이 맞는 동안에만 도메인(과 하위 도메인)을 허용. 그룹으로 묶어 켜고 끌 수 있음 |
| 앱 제거 | 비밀번호를 새로 입력하면 모든 제한을 풀고 Device Owner 를 내려놓은 뒤 시스템 제거 화면을 띄움 |
| 비밀번호 | PBKDF2 해시 저장, 복구 기능 없음, 연속 실패 시 대기 시간 증가, 입력 후 5분간 편집 가능 |
| 공장 초기화 | 막지 않음 (최후의 복구 수단) |

미구현: 위치 예외, 강력 모드.

## 네트워크 화이트리스트 동작과 한계

- `setRecommendedGlobalProxy` 로 프록시를 `127.0.0.1:9`(열려 있지 않은 포트)로 지정하고, 허용 도메인을 프록시 **예외 목록**에 넣습니다. 예외 목록의 주소는 프록시를 거치지 않고 바로 접속하며, 나머지는 닫힌 포트로 가서 실패합니다.
- 도메인 하나를 넣으면 `도메인`과 `*.도메인` 두 항목이 들어갑니다(클라이언트마다 와일드카드 해석이 달라서).
- 시스템 연결 확인용 주소(`connectivitycheck.gstatic.com` 등)는 항상 허용합니다.
- **한계**: 시스템 프록시 설정을 따르는 앱(브라우저, 대부분의 HTTP 앱)만 걸러집니다. 프록시를 무시하는 앱(일부 게임·메신저의 자체 소켓, UDP/QUIC 직접 연결 등)은 이 방식으로 막을 수 없습니다. 모든 앱을 강제하려면 VPN 잠금(Always-on VPN + 차단) 방식이 필요한데, 이 앱은 VPN을 쓰지 않는 쪽을 택했습니다.
- 안드로이드는 형식이 틀린 프록시 설정을 **조용히 무시**합니다. 그래서 입력 단계에서 같은 규칙으로 걸러내고(한글 도메인의 punycode `xn--` 처럼 하이픈이 연속되는 주소, IPv6, 점 없는 이름은 거부), 적용 후 실제 반영 여부를 확인해 상태 카드에 표시합니다.
- 예외 목록 길이 한도(5000자)가 있어 허용 도메인이 너무 많으면 저장이 거부됩니다.
- 허용 규칙이 하나도 없는 채로 켜면 인터넷이 사실상 모두 끊깁니다(켤 때 경고).

## 삭제·재설치 처리

- 규칙에 등록된 앱이 삭제되면 상태 카드에 "설치되지 않은 규칙 앱"으로 따로 표시하고(시스템 거부와 구분), 규칙은 유지됩니다.
- 앱을 삭제했다가 다시 설치하면 일시중지 상태가 사라지므로, 다시 차단해야 합니다. 앱 삭제는 `PACKAGE_FULLY_REMOVED` 로 즉시 감지하고, 미설치 앱이 있는 동안에는 5분마다, 평소에는 30분마다 다시 평가합니다. (Android 8 이상에서는 `PACKAGE_ADDED` 를 매니페스트로 못 받을 수 있어 짧은 주기 평가를 겸합니다. 재설치 직후 최대 5분 정도는 열릴 수 있습니다.)
- 앱 선택 창은 열려 있는 동안 설치/삭제 이벤트를 받아 목록을 자동 갱신하고, 이미 선택했지만 삭제된 앱도 목록에 남겨 선택을 해제할 수 있게 합니다.

## 비밀번호로 앱 제거

메인 화면 맨 아래 "비밀번호로 앱 제거". 편집 잠금 해제와 별개로 비밀번호를 매번 새로 확인하고, 한 번 더 확인한 뒤 다음 순서로 진행합니다: 앱 차단 해제 → 프록시 해제 → 사용자 제한 해제 → 제거 차단 해제 → `clearDeviceOwnerApp` → 시스템 제거 화면. Device Owner 해제에 실패하면 제한을 다시 걸고 실패 사유를 보여 줍니다. 제거 화면에서 취소하면 제한이 풀린 채 남습니다.

## 빌드

1. Android Studio에서 `DeviceLock` 폴더를 엽니다. Gradle 동기화가 끝날 때까지 기다립니다.
2. 버전 관련 오류가 나면 AGP 8.7.3, Kotlin 2.0.21, Compose BOM 2024.12.01 을 설치된 Studio에 맞게 올려 주세요.
3. 개발 중에는 Studio의 Run으로 설치하는 것을 권장합니다. 일반적으로 이 방식은 테스트용 플래그가 붙어 adb로 Device Owner를 해제할 수 있습니다(확실하지 않으므로 반드시 테스트 기기로 먼저 확인하세요).

## Device Owner 설정

1. 기기에서 모든 계정(구글 등)을 제거합니다.
2. 개발자 옵션에서 USB 디버깅을 켜고 PC와 연결합니다.
3. 앱을 설치한 뒤 PC에서 실행합니다.

```
adb shell dpm set-device-owner app.devicelock/.DeviceLockAdminReceiver
```

4. 앱을 열고 비밀번호를 설정합니다.

제조사에 따라 이 명령이 거부될 수 있습니다.

## 주의

- 릴리스 빌드를 Device Owner로 설정하면 디버깅이 막혀 adb로도 되돌릴 수 없고, 공장 초기화만 가능합니다. **주 기기에 적용하기 전에 테스트 기기에서 먼저 검증하세요.**
- 앱은 자기 자신, 전화, 설정, 런처 등 시스템이 일시중지를 거부하는 패키지는 차단하지 못합니다. 거부된 패키지는 상태 카드에 빨간 글씨로 표시됩니다.
- Android 12/12L에서는 정확 알람 권한이 없으면 규칙 전환이 몇 분 늦을 수 있습니다. Android 13 이상은 자동으로 허용됩니다.
- 시간 서버는 시스템이 정하며 앱이 지정할 수 없습니다.
- 막지 않는 것(의도): 공장 초기화, 출처를 알 수 없는 앱 설치. 같은 서비스의 다른 패키지(비공식 앱 등)를 설치하면 별도 규칙이 필요합니다.

## 1단계 검증 체크리스트 (실기기)

1. Device Owner 설정 후 앱의 상태 카드에 실패 항목이 없는지 확인
2. 설정 > 앱 에서 이 앱의 삭제, 강제 종료, 저장공간 삭제가 막혀 있는지 확인
3. 날짜/시간 설정을 수동으로 바꿀 수 없는지 확인
4. 테스트 앱 하나로 규칙을 만들어 지금 시각에 걸리게 하고 실행/알림이 막히는지 확인
5. 시간대를 바꿔 규칙 경계(예: 1~2분 뒤)에서 자동으로 적용·해제되는지 확인
6. 재부팅 후에도 상태가 유지되는지 확인
7. 비밀번호 없이 규칙을 수정할 수 없는지, 5회 오입력 시 대기가 걸리는지 확인
8. 규칙에 등록한 앱을 삭제했다가 다시 설치했을 때, 몇 분 안에 다시 차단되는지 / 삭제 중에 상태 카드에 "설치되지 않은 규칙 앱"으로 뜨는지 확인
9. 화이트리스트를 켜고 허용 도메인 하나만 등록한 뒤, 크롬에서 허용 사이트는 열리고 다른 사이트는 막히는지 확인. 상태 카드에 네트워크 오류가 없는지 확인
10. 도메인 허용 규칙을 "지금 시각이 아닌 시간대"로 만들면 막히고, 시간대를 포함하게 고치면 열리는지 확인 (경계 시각에서 자동 전환되는지도)
11. 삼성 보안 폴더·듀얼 메신저·보조 사용자 추가가 막혀 있는지 확인(제조사별로 다를 수 있음)
12. **테스트 기기에서 먼저** "비밀번호로 앱 제거"를 눌러 Device Owner 해제 → 제거까지 끝나는지 확인 (OS 버전에 따라 `clearDeviceOwnerApp` 동작이 다를 수 있음)

## 스마트 스위치 (실험 기능)

삼성 스마트 스위치는 Device Owner 상태에서 기본 차단됩니다. 앱 메인 화면의 "스마트 스위치 허용" 스위치를 켜면
`com.sec.android.easyMover` 에 관리 구성 값 `allow_run=true` 를 넣습니다. 이 방식이 실제로 동작하는지는 검증되지 않았으므로 실기기에서 확인이 필요합니다.

같은 스위치가 `setBackupServiceEnabled`(백업 서비스 허용)도 함께 제어합니다. 관리 서비스 문서들이 두 설정을 같이 켜라고 안내하기 때문입니다. 끄면 백업 서비스는 다시 비활성이 됩니다.
